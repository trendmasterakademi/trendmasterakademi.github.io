The developer who built the platform departed. The site continues running but cannot be modified: repository location, server SSH credentials, or account ownership remain unknown. These are three distinct bottlenecks, identifiable within hour one.

Urgency: High · continuity risk · Category: Handover & Continuity

Field Observations

The sole developer behind the project departs or cuts communication. When emergency updates arise, the agency discovers nobody holds Git repo permissions, server keys, or deployment credentials; the company is locked out of its own software.

Observed System Error Signatures

  • git log -1 --format=%cd <- timestamp of last commit?
  • git log --format='%an' | sort -u <- how many contributors touched code?
  • ~/.ssh/authorized_keys <- who has SSH keys to production?
  • WHOIS + cloud account <- registered to which email?

These four checkpoints determine whether handover failure is technical or administrative. In most cases, the bottleneck is account ownership rather than code.

Three Potential Root Causes & Differential Tests

A · Loss of access

Domain registrar, host, and git repos are registered to personal emails. Code and infrastructure are sound; the bottleneck is credential handover.

Differential test: Are accounts tied to company domain email?

Evidence: Accounts on personal mail → A

Resolution: Account transfer — admin workflow, no coding needed

Common anti-pattern fix: Requesting passwords via messaging apps fails when outdated credentials run straight into two-factor authentication prompts on personal devices.

B · Missing source repository

Version control was never initialized. Live production server contains the sole surviving copy. The highest-risk state.

Differential test: Is version control (git remote) present?

Evidence: No remote repo → B

Resolution: Full live image FIRST, then git init setup

Common anti-pattern fix: Tasking a replacement developer to reverse-engineer environment setups wastes days resolving undocumented build flags and missing local dependencies.

C · Undocumented environment

Repository exists but cannot be booted: setup commands, environment variables, and lockfiles are absent.

Differential test: Are README and package lockfiles available?

Evidence: Missing .env / lockfile → C

Resolution: Environment rebuild + documentation

Common anti-pattern fix: Downloading production files via FTP yields minified bundles; lacking original source code makes subsequent feature updates and debugging impractical.

Resolution Path & Time to Fix

A is an administrative process, requiring zero coding. For B, the absolute first step is pulling a full live server image, not writing code. C is precisely what a handover code audit diagnoses.

Impact If Left Unresolved

Without version control, production is a single point of total failure. If the instance crashes, recovery is impossible. Risk compounds daily until full image verification is completed.
