Specific operations — checkout completion, stock updates, or batch imports — hang indefinitely until timeout. The server has not crashed; concurrent transactions are locked waiting for each other.

Urgency: Critical · transaction halt · Category: Performance

Field Observations

When users submit forms or proceed to checkout, the browser tab spinner spins indefinitely. The page hangs white without showing errors; simultaneously, incoming visitors cannot even connect to the homepage.

Observed System Error Signatures

  • Deadlock found when trying to get lock; try restarting transaction → A · Cross-ordered row locks
  • Lock wait timeout exceeded; try restarting transaction → B · Long-running transaction
  • Database holds long-running idle in transaction locks → B · Long-running transaction
  • App logs: two concurrent batch updates in same second

'try restarting transaction' is the database engine's explicit diagnosis. When logged, root cause is verified deadlock.

Three Potential Root Causes & Differential Tests

A · Cross-ordered row locks

Two transactions update tables in reverse order; each blocks waiting for the other's release.

Differential test: Are deadlock / lock wait errors present in logs?

Evidence: Deadlock found in database log → A

Resolution: Enforce global consistent lock acquisition order

Common anti-pattern fix: Restarting the database service resets locks, but identical SQL transaction sequencing promptly deadlocks the tables under the next traffic burst.

B · Long-running transaction

Transaction wraps external API calls or PDF generation, holding database row locks for minutes.

Differential test: Do open DB locks persist for multiple minutes?

Evidence: Idle in transaction > 60s → B

Resolution: Move external I/O outside of SQL transactions

Common anti-pattern fix: Moving reporting queries to midnight fails over time as growing data sets spill into morning hours, freezing live transactional operations.

C · Broad table lock (Batch)

Nightly batch import locks wide index ranges, starving real-time checkout threads.

Differential test: Do lock spikes overlap with cron batch execution?

Evidence: Deadlock coincides with cron batch → C

Resolution: Chunk batch updates + off-peak queue scheduling

Common anti-pattern fix: Doubling worker pool limits fails because unaddressed database bottlenecks cause all newly spawned processes to lock and saturate within seconds.

Resolution Path & Time to Fix

Senior backend engineer. Database engine outputs the conflicting queries in crash logs; resolution requires re-ordering table mutations and scoping transaction lifecycles.

Impact If Left Unresolved

Deadlocks compound during peak traffic campaigns. Their insidious nature is selective failure: catalogs browse fine while core checkout operations grind to a halt.
