Trivial edits like updating button styles or adding a form field drag on for days, leading clients to assume reluctance. The root cause is not developer speed, but the cognitive overhead of deciphering undocumented code.

Urgency: Medium · velocity loss · Category: Code Health

Field Observations

Minor adjustments like adding a menu link or a phone field to a form drag on for weeks. Clients assume deliberate procrastination; in reality, developers spend hours hunting through tangled files just to locate the markup.

Observed System Error Signatures

  • Task duration: 2h estimated, 2 days actual delivery
  • Onboarding: how many days for new engineer to boot project?
  • Documentation exists: setup guide, architecture schema, ADRs?
  • Deploy cadence: how many production releases per week?

The clearest benchmark is time-to-first-commit for a new developer. If local onboarding takes longer than one day, velocity loss stems from developer experience, not individual talent.

Three Potential Root Causes & Differential Tests

A · Zero developer documentation

Domain knowledge exists solely in individuals' memories. Every change requires historical code archaeology.

Differential test: Can a new dev boot the project locally within 1 day?

Evidence: Missing README / architecture docs → A

Resolution: Write README setup + architecture decision records

Common anti-pattern fix: Blindly grepping across repositories without architectural documentation leads to editing the wrong component overrides, wasting hours of engineering time.

B · Manual deployment ceremony

Deployments rely on manual FTP / SSH commands; tiny tweaks require extensive manual rituals.

Differential test: Is deployment automated with a single command?

Evidence: Manual FTP/SSH release steps → B

Resolution: Automate CI/CD · one-click release pipeline

Common anti-pattern fix: Overwriting live files via FTP skips version control and automated linting, turning a single misplaced character into an instant site outage.

C · Unstructured spaghetti architecture

Locating which file controls the feature takes hours; scattered business logic and inconsistent naming conventions.

Differential test: Does locating target logic require hours of grep searching?

Evidence: Hours spent locating source code file → C

Resolution: Apply Scout Rule: clean up target module gradually

Common anti-pattern fix: Stacking !important rules in CSS to force styles temporarily overrides layout issues while making subsequent UI maintenance virtually impossible.

Who resolves it

None of these are resolved by 'working overtime'. The payoff is not immediate; it builds up: the same team ships noticeably more work in the same time.

Impact If Left Unresolved

Sluggish delivery erodes client relationships. Clients interpret delays as neglect, while engineers burn out operating in an unmaintained codebase.
